السكشن الأول: إنشاء الجداول والـ Constraints وحذفها

نبدأ الأول بتشريح كل أمر وكل قيد في السكشن الأول (صيغته العامة ووظيفته وشروطه)، وبعدها ندخل في الشرح التفصيلي لأكواد السكشن والمقارنات والتطبيق الشامل.

🔍 أولاً: تشريح وشرح كل أمر وكل قيد في السكشن الأول (الصيغة العامة + الوظيفة)

قبل ما نقرأ أمثلة السكشن، تعالَ نمسك كل أمر وكل كلمة في السكشن الأول ونفهم الصيغة العامة بتاعتها (General Syntax) وبتشتغل إزاي:

١. أمر إنشاء الجدول: CREATE TABLE أمر هيكلي — DDL

وظيفته: ينشئ جدولاً جديداً في قاعدة البيانات، ونحدد بداخله اسم كل عمود، ونوع البيان Datatype، والقيمة الافتراضية أو القيود إن وجدت.

أشهر أنواع البيانات (Datatypes) في السكشن:

  • NUMBER: لتخزين الأرقام (سواء صحيحة أو عشرية).
  • VARCHAR2(size): لتخزين النصوص والحروف بحد أقصى size حرف (مثلاً varchar2(50)).
  • DATE: لتخزين التاريخ والوقت.
SYNTAX: CREATE TABLE 
CREATE TABLE table_name (
    column1_name datatype [DEFAULT expr] [column_constraint],
    column2_name datatype [DEFAULT expr] [column_constraint],
    [table_constraint (column_name)]
);
٢. قيد عدم الفراغ: NOT NULL يكتب Column-Level فقط

وظيفته: يجبر المستخدم على إدخال قيمة في هذا العمود عند إضافة أي صف، ويمنع تركه فارغاً (NULL). شرطه: يكتب فقط بجوار العمود (Column-Level) ولا يكتب في نهاية الجدول.

SYNTAX: NOT NULL 
-- بدون تسمية القيد:
column_name datatype NOT NULL

-- مع تسمية القيد:
column_name datatype CONSTRAINT constraint_name NOT NULL
٣. قيد عدم التكرار: UNIQUE Column-Level أو Table-Level

وظيفته: يمنع تكرار نفس القيمة مرتين في نفس العمود، لكنه يسمح بترك الخانة فارغة (NULL).

SYNTAX: UNIQUE 
-- 1. على مستوى العمود (Column-Level):
column_name datatype [CONSTRAINT const_name] UNIQUE

-- 2. على مستوى الجدول في النهاية (Table-Level):
CONSTRAINT const_name UNIQUE (column_name)
٤. قيد المفتاح الأساسي: PRIMARY KEY واحد فقط لكل جدول

وظيفته: يميز كل صف في الجدول بشكل فريد، وهو يدمج شرطي (NOT NULL + UNIQUE) معاً. لا يجوز أن يحتوي الجدول على أكثر من Primary Key واحد، وإذا كان مركباً من عمودين (Composite PK) يجب كتابته في نهاية الجدول (Table-Level).

SYNTAX: PRIMARY KEY 
-- 1. على مستوى العمود (لعمود واحد فقط):
column_name datatype [CONSTRAINT const_name] PRIMARY KEY

-- 2. على مستوى الجدول (لعمود واحد أو Composite PK من عمودين):
CONSTRAINT const_name PRIMARY KEY (col1, col2)
٥. قيد الفحص والشرط: CHECK (condition) Column-Level أو Table-Level

وظيفته: يضع شرطاً منطقياً على القيم المسموح بإدخالها في العمود (مثل أن يكون العمر أو الرقم أكبر من صفر). إذا أدخل المستخدم قيمة تخالف الشرط يرفضها أوراكل فوراً.

SYNTAX: CHECK 
-- 1. على مستوى العمود:
column_name datatype [CONSTRAINT const_name] CHECK (column_name > 0)

-- 2. على مستوى الجدول:
CONSTRAINT const_name CHECK (column_name > 0)
٦. القيمة الافتراضية: DEFAULT value تكتب قبل الـ Constraint دائماً

وظيفته: يحدد قيمة جاهزة توضع تلقائياً في العمود إذا لم يقم المستخدم بإدخال قيمة له أثناء الـ INSERT. قاعدة هامة: تكتب كلمة DEFAULT بعد نوع البيان مباشرةً وقبل أي Constraint.

SYNTAX: DEFAULT 
column_name datatype DEFAULT default_value [CONSTRAINT const_name] [NOT NULL]
٧. قيد المفتاح الأجنبي: FOREIGN KEY / REFERENCES ربط الجدول الابن بالجدول الأب

وظيفته: يربط عموداً في الجدول الابن بالـ Primary Key في الجدول الأب. لاحظ اختلاف الصيغة بين مستوى العمود ومستوى الجدول:

SYNTAX: FOREIGN KEY 
-- 1. على مستوى العمود (نكتب REFERENCES مباشرة بدون كلمة FOREIGN KEY):
fk_column datatype [CONSTRAINT fk_name] REFERENCES parent_table (pk_column)

-- 2. على مستوى الجدول (يجب كتابة FOREIGN KEY (fk_column) أولاً):
CONSTRAINT fk_name FOREIGN KEY (fk_column) REFERENCES parent_table (pk_column)
٨. أمرا هدم وتفريغ الجدول: DROP TABLE و TRUNCATE TABLE أوامر هيكلية — DDL

وظيفة DROP TABLE: يحذف الجدول بالكامل (البيانات + الهيكل + الأعمدة + القيود) من قاعدة البيانات.
وظيفة TRUNCATE TABLE: يفرغ الجدول من جميع الصفوف والبيانات دفعة واحدة، مع الإبقاء على هيكل الجدول وأعمدته سليمة.

SYNTAX: DROP & TRUNCATE 
DROP TABLE table_name;
TRUNCATE TABLE table_name;

📌 ثانياً: الفرق بين عائلات أوامر SQL الثلاثة

لازم تفرق بين الـ 3 عائلات الأساسية لأوامر SQL اللي موجودة في السكشن عندك لأن المقارنة بينهم سؤال أساسي في أي امتحان:

وجه المقارنة أوامر DDL أوامر DML أوامر TCL
الاسم الكامل Data Definition Language Data Manipulation Language Transaction Control Language
بتتعامل مع إيه؟ بتتعامل مع هيكل الجدول نفسه (إنشاء جدول، تعديل أعمدة، مسح جدول) بتتعامل مع البيانات والصفوف اللي جوه الجدول (إضافة، تعديل، مسح داتا) بتتحكم في تثبيت وحفظ أو إلغاء التغييرات اللي عملتها بأوامر الـ DML
الأوامر الخاصة بيها CREATE , ALTER , DROP , TRUNCATE INSERT , UPDATE , DELETE COMMIT , ROLLBACK
الحفظ التلقائي (Auto-Commit) نعم تحفظ تلقائياً ومينفعش تعمل بعدها ROLLBACK لا تحفظ تلقائياً لازم تكتب COMMIT عشان تثبت، وتقدر تتراجع عنها بـ ROLLBACK هي المسؤولة أصلاً عن الحفظ أو التراجع

🛡️ ثالثاً: شرح أكواد السكشن الأول لأنواع الـ Constraints الخمسة والـ Default

لما بنبني عمود في جدول، بنحدد الشروط اللي تحمي الداتا بتاعته باستخدام الـ Constraints الآتية:

  1. قيد NOT NULL: بيمنع إن العمود يتساب فاضي، يعني إجباري تدخل فيه قيمة في كل صف.
  2. قيد UNIQUE: بيمنع تكرار نفس القيمة مرتين في نفس العمود (زي الإيميل أو رقم التليفون)، لكن لو سبت الخانة فاضية NULL بيسمح عادي.
  3. قيد PRIMARY KEY: ده أهم قيد في الجدول (بيميز كل صف عن غيره)، وهو عبارة عن NOT NULL + UNIQUE مع بعض (يعني ممنوع يتكرر وممنوع يتساب فاضي). وأي جدول في الدنيا مينفعش يكون فيه غير Primary Key واحد بس.
  4. قيد CHECK (condition): بتحط بيه شرط منطقي على القيم اللي داخلة، زي إن الرقم يكون أكبر من صفر check(Dssn > 0)، ولو دخلت قيمة تخالف الشرط أوراكل بيرفضها.
  5. قيد FOREIGN KEY (REFERENCES): ده العمود اللي بيربط جدول بجدول تاني (يربط الجدول الابن بالـ Primary Key بتاع الجدول الأب)، وبيشترط إن القيمة اللي تدخلها فيه تكون موجودة أصلاً في الجدول الأب.
  6. خاصية DEFAULT: بتدي قيمة افتراضية للعمود، بحيث لو المستخدم مدخلش قيمة للعمود ده في الـ INSERT، أوراكل ينزل القيمة الافتراضية دي تلقائياً بدل ما يسيبه NULL.

وده الكود الأول في السكشن عندك (يُقرأ من الشمال لليمين):

ORACLE SQL — COLUMN CONSTRAINTS & DEFAULT 
create table Doctors(
    Dssn number not null,          -- 1. إجباري الإدخال (ممنوع يكون NULL)
    Dssn number unique,            -- 2. ممنوع القيمة تتكرر، بس يقبل NULL
    Dssn number primary key,       -- 3. مفتاح أساسي (Not Null + Unique معاً)
    Dssn number check(Dssn > 0),   -- 4. شرط أن تكون القيمة أكبر من صفر
    Dssn number default 1          -- 5. لو مدخلتش قيمة، هياخد 1 تلقائياً
);

جدول مقارنة شامل بين الـ Constraints الخمسة (مهم جداً للامتحانات):

نوع الـ Constraint هل يسمح بتكرار القيمة؟ هل يسمح بقيمة NULL؟ كم مرة يمكن استخدامه في الجدول الواحد؟
PRIMARY KEY لا يسمح أبداً لا يسمح أبداً مرة واحدة فقط في الجدول كله
UNIQUE لا يسمح أبداً نعم يسمح بـ NULL أي عدد من الأعمدة براحتك
NOT NULL نعم يسمح بالتكرار لا يسمح أبداً أي عدد من الأعمدة براحتك
CHECK نعم يسمح (طالما يحقق الشرط) نعم يسمح (إلا لو منعته) أي عدد من الأعمدة براحتك
FOREIGN KEY نعم يسمح بالتكرار نعم يسمح (إلا لو حطيت جنبه NOT NULL) أي عدد من الأعمدة حسب العلاقات

🏷️ رابعاً: تسمية الـ Constraint وترتيب الـ DEFAULT

1. الفرق بين Unnamed Constraint و Named Constraint:

بص على السطرين دول في كود السكشن عندك:

UNNAMED VS NAMED CONSTRAINT 
Dssn number primary key,                       -- Unnamed Constraint
Dssn number constraint dssn_const primary key, -- Named Constraint
السطر الأول (Unnamed Constraint): كتبت نوع القيد علطول من غير ما تسميه. أوراكل هيقبله وهيسميه من عنده اسم عشوائي في السيستم (زي SYS_C007482). عيبه إنك لو حبيت تعمل له DROP أو DISABLE بعدين، مش هتعرف اسمه بسهولة!
السطر الثاني (Named Constraint): كتبت كلمة constraint وبعدها اسم من اختيارك (dssn_const) وبعدين نوع القيد. ودي الطريقة الصح دايماً عشان تقدر تتحكم في الـ Constraint باسمه في أي وقت.

2. قاعدة ترتيب DEFAULT مع الـ Constraint:

بص على السطرين اللي بعدهم في كودك:

DEFAULT ORDERING 
Dssn number default 5 not null,
Dssn number default 5 constraint nn_const not null,
⚠️ قاعدة ذهبية للامتحان

لو العمود واخد DEFAULT وواخد Constraint في نفس السطر، لازم DEFAULT تتكتب الأول بعد الـ Datatype مباشرة، وبعدها ييجي الـ Constraint في الآخر. لو عكستهم أوراكل هيطلع Syntax Error فوراً!

⚖️ خامساً: المقارنة الكبرى بين Column-Level و Table-Level Constraints

في كود السكشن عندك هتلاقي علامات xxxxxxx على سطرين؛ العلامات دي المعيد حاططها عشان ينبهك لأخطاء مشهورة بتيجي في الامتحانات. تعالى نفهم الفرق بين الطريقتين وليه السطرين دول غلط:

1. الطريقة الأولى: Column-Level Constraint (على مستوى العمود)

يعني بتكتب الـ Constraint في نفس سطر تعريف العمود جنب الـ Datatype مباشرة. الطريقة دي ممتازة لو القيد على عمود واحد، لكن مستحيل تعمل بيها Composite Primary Key (مفتاح أساسي مركب من عمودين)!

ERROR 1: COMPOSITE PK AT COLUMN LEVEL 
-- ❌ xxxxxxx composite primary key (غلط تماماً في أوراكل)
dssn number primary key ,
name varchar2(50) primary key ,
❌ ليه الكود ده عليه علامة xxxxxxx (غلط)؟

لأن الجدول الواحد مينفعش يكون فيه اتنين PRIMARY KEY منفصلين! لما تكتب primary key جنب العمود الأول وترجع تكتبها جنب العمود التاني، أوراكل هيطلع خطأ. لو عايز تعمل Composite Primary Key من عمودين مع بعض، إجباري تعمله بالطريقة التانية (Table-Level).

2. الطريقة الثانية: Table-Level Constraint (على مستوى الجدول)

يعني بتعرف كل الأعمدة الأول عادي خالص، وبعد ما تخلص الأعمدة تنزل في آخر الجدول تكتب الـ Constraints وتحدد اسم العمود بين قوسين:

TABLE LEVEL CONSTRAINTS & ERROR 2 
create table Doctors(
    Dssn number,
    name varchar2(50),
    -- ✅ كتابة القيود على مستوى الجدول (نحدد اسم العمود بين قوسين):
    constraint pk_const primary key (Dssn),
    constraint uni_const unique (name)
    -- ✅ ولو عايز Composite Primary Key من العمودين معاً تتكتب هنا كده:
    -- constraint pk_comp primary key (Dssn, name)

    -- ❌ xxxxx constraint nn_cons not null() (غلط تماماً على مستوى الجدول)
);
❌ ليه سطر الـ NOT NULL عليه علامة xxxxx (غلط)؟

لأن قيد الـ NOT NULL هو القيد الوحيد اللي ممنوع يتكتب Table-Level بالصيغة دي في آخر الجدول! لازم دايماً يتكتب Column-Level جنب العمود نفسه فوق.

جدول مقارنة يحسم الفرق بين Column-Level و Table-Level:

وجه المقارنة Column-Level Constraint Table-Level Constraint
مكانه في الكود جنب اسم العمود ونوعه في نفس السطر في آخر جملة CREATE TABLE بعد تعريف كل الأعمدة
كتابة اسم العمود بين قوسين لا نكتبه لأنه مكتوب جنب العمود أصلاً إجباري نكتب اسم العمود بين قوسين
عمل Composite Primary Key مستحيل (يعطي Error) نعم، هو الطريقة الوحيدة مثلاً PRIMARY KEY (col1, col2)
كتابة قيد NOT NULL نعم، يكتب هنا فقط ممنوع (لا توجد صيغة not null(col))
طريقة كتابة الـ Foreign Key بنكتب REFERENCES parent_table(col) علطول بدون كلمة FOREIGN KEY لازم نكتب FOREIGN KEY (col) REFERENCES parent_table(col)

🔗 سادساً: تطبيق الـ Foreign Key + الفرق بين DROP و TRUNCATE

في الكود عندك، أنشأ جدول Doctors الأول، وبعدين أنشأ جدول Patients وربطه بجدول الدكاترة عن طريق الـ Foreign Key بالطريقتين (Column-Level و Table-Level):

FOREIGN KEY (COLUMN VS TABLE LEVEL) & DROP / TRUNCATE 
-- 1. إنشاء الجدول الأب أولاً (Doctors):
create table Doctors (
    Dssn number primary key,
    name varchar2(50) not null,
    speciality varchar2(100) not null,
    exp_years number not null
);

-- 2. الطريقة الأولى: Foreign Key على مستوى العمود (Column-Level)
-- لاحظ: بنكتب references علطول ومبنكتبش جملة foreign key
create table patients (
    ssn number primary key ,
    name varchar2(50) not null,
    age number not null,
    address varchar2(100) not null,
    dssn number references doctors (dssn)
    -- أو مع تسمية القيد:
    -- dssn number constraint dssn_fk references doctors (dssn)
);

-- 3. الطريقة الثانية: Foreign Key على مستوى الجدول (Table-Level)
-- لاحظ: لازم نكتب foreign key (dssn) الأول قبل references
create table patients (
    ssn number primary key ,
    name varchar2(50) not null,
    age number not null,
    address varchar2(100) not null,
    dssn number ,
    constraint dssn_fk foreign key (dssn) references doctors (dssn)
);

-- 4. مسح الجدول بالكامل مقابل تفريغ البيانات فقط:
drop table patients;
truncate table patients;
أمر DROP TABLE patients;: بيمسح الجدول بالكامل من الداتابيز (بيمسح الصفوف + الأعمدة + القيود + هيكل الجدول نفسه).
أمر TRUNCATE TABLE patients;: بيمسح كل الصفوف والبيانات اللي جوه الجدول بس، لكن بيسيب هيكل الجدول وأعمدته وقيوده موجودين وجاهزين تدخل فيهم داتا جديدة.

💻 مثال تطبيقي شامل يجمع كل قواعد Section 1 مرة واحدة

ده كود مجمع بيطبق كل اللي اتشرح في السكشن الأول (Primary Key، Foreign Key، Unique، Not Null، Check، Default، Column-Level، و Table-Level) في مثال واحد متكامل:

SECTION 1 MASTER PRACTICE SCRIPT 
-- 1. إنشاء جدول الدكاترة بكل القيود على مستوى العمود (Column-Level):
CREATE TABLE Doctors (
    Dssn number constraint doc_pk primary key,
    name varchar2(50) constraint doc_name_nn not null,
    speciality varchar2(100) default 'General' not null,
    exp_years number default 1 not null constraint doc_exp_chk check (exp_years >= 0)
);

-- 2. إنشاء جدول المرضى بدمج Column-Level مع Table-Level:
CREATE TABLE Patients (
    ssn number,
    name varchar2(50) not null,
    age number not null,
    address varchar2(100) default 'Zagazig' not null,
    phone varchar2(20),
    dssn number,
    -- القيود على مستوى الجدول (Table-Level):
    constraint pat_pk primary key (ssn),
    constraint pat_phone_uni unique (phone),
    constraint pat_age_chk check (age > 0),
    constraint pat_doc_fk foreign key (dssn) references Doctors (Dssn)
);

-- 3. تجربة تفريغ جدول المرضى (يبقى الهيكل كما هو):
TRUNCATE TABLE Patients;

-- 4. تجربة حذف جدول المرضى بالكامل (يمسح الهيكل والبيانات):
DROP TABLE Patients;

Section 2 — Part 1 (ALTER TABLE)

السكشن الثاني (الجزء الأول): التعديل على هيكل الجدول بـ ALTER TABLE

نبدأ الأول بتشريح كل أمر من أوامر ALTER TABLE وصيغته العامة، وبعدها ندخل في شرح الـ ١١ عملية اللي في كود السكشن بالتفصيل والمقارنات والتطبيق الشامل.

🔍 أولاً: تشريح وشرح كل أمر من أوامر ALTER TABLE بالتفصيل (الصيغة العامة + الوظيفة)

أمر ALTER TABLE هو الأمر المسؤول عن أي تعديل في هيكل جدول موجود بالفعل، وبيجي معاه ٧ كلمات أساسية في السكشن عندك:

١. أمر إضافة الأعمدة: ALTER TABLE ... ADD لإضافة عمود جديد أو أكثر

وظيفته: يضيف عموداً جديداً (أو عدة أعمدة بين قوسين) إلى جدول موجود. يمكنك إضافة DEFAULT أو Constraint مع العمود الجديد في نفس السطر.

SYNTAX: ALTER TABLE ADD 
-- إضافة عمود واحد:
ALTER TABLE table_name ADD column_name datatype [DEFAULT expr] [constraint];

-- إضافة عدة أعمدة معاً (يجب وضعهم بين قوسين):
ALTER TABLE table_name ADD (col1 datatype, col2 datatype, ...);
٢. أمر تعديل خصائص عمود: ALTER TABLE ... MODIFY لتعديل عمود موجود بالفعل

وظيفته: يعدل عموداً موجوداً مسبقاً في الجدول لتغيير نوع البيان (Datatype)، أو تكبير حجمه (Size)، أو تحويله إلى NOT NULL أو إرجاعه ليقبل NULL.

SYNTAX: ALTER TABLE MODIFY 
-- تغيير النوع أو الحجم:
ALTER TABLE table_name MODIFY column_name new_datatype(new_size);

-- تحويل العمود إلى إجباري أو اختياري:
ALTER TABLE table_name MODIFY column_name NOT NULL;
ALTER TABLE table_name MODIFY column_name NULL;
٣. أمر حذف الأعمدة: ALTER TABLE ... DROP انتبه لقاعدة كلمة COLUMN

وظيفته: يحذف عموداً أو عدة أعمدة نهائياً من الجدول. القاعدة الذهبية: مع عمود واحد نكتب كلمة COLUMN بدون أقواس، ومع عدة أعمدة نستخدم الأقواس فقط ونحذف كلمة COLUMN.

SYNTAX: ALTER TABLE DROP COLUMN(S) 
-- حذف عمود واحد فقط:
ALTER TABLE table_name DROP COLUMN column_name;

-- حذف عدة أعمدة معاً:
ALTER TABLE table_name DROP (col1, col2, col3);
٤. أمر إعادة التسمية: RENAME COLUMN و RENAME TO تغيير اسم عمود أو جدول

وظيفته: يغير اسم عمود داخل الجدول، أو يغير اسم الجدول نفسه بدون المساس بالبيانات المسجلة بداخله.

SYNTAX: RENAME COLUMN & TABLE 
-- تغيير اسم عمود:
ALTER TABLE table_name RENAME COLUMN old_col_name TO new_col_name;

-- تغيير اسم الجدول نفسه:
ALTER TABLE old_table_name RENAME TO new_table_name;
٥. أوامر إدارة القيود: ADD / DROP / DISABLE / ENABLE CONSTRAINT التحكم الكامل في الـ Constraints

وظيفتها: تمكنك من إضافة قيد جديد لجدول بعد إنشائه، أو حذفه نهائياً باسمه، أو إيقافه مؤقتاً (DISABLE) وإعادة تشغيله (ENABLE).

SYNTAX: MANAGE CONSTRAINTS 
-- 1. إضافة قيد جديد:
ALTER TABLE table_name ADD CONSTRAINT const_name constraint_type (column_name);

-- 2. حذف قيد نهائياً:
ALTER TABLE table_name DROP CONSTRAINT const_name;

-- 3. تعطيل وتفعيل قيد مؤقتاً:
ALTER TABLE table_name DISABLE CONSTRAINT const_name;
ALTER TABLE table_name ENABLE CONSTRAINT const_name;

➕ ثانياً: العمليات (١ و ٢ و ٣) — إضافة أعمدة جديدة بـ ADD

نستخدم ALTER TABLE table_name ADD لما نحب نضيف عمود أو أكتر مكنوش موجودين أصلاً في الجدول:

  1. إضافة عمود واحد أو عدة أعمدة: لو عمود واحد بنكتبه بدون أقواس، ولو أكتر من عمود بنحطهم بين قوسين وبينهم فاصلة.
  2. إضافة عمود مع DEFAULT: لو الجدول كان فيه صفوف قديمة، العمود الجديد هيتضاف وياخد القيمة الافتراضية دي لكل الصفوف القديمة والجديدة.
  3. إضافة عمود مع Constraint: نقدر نضيف عمود ونحط معاه NOT NULL أو CHECK في نفس السطر.
⚠️ ملاحظة مهمة جداً في الامتحان والعملي

عشان تضيف عمود جديد وعليه قيد NOT NULL بدون DEFAULT، لازم الجدول يكون فاضي تماماً مفهوش أي صفوف قديمة؛ لأن لو فيه صفوف قديمة هتاخد إيه في العمود الجديد؟ فلو الجدول فيه داتا، لازم إما تفضيه الأول أو تحط مع العمود DEFAULT value.

ALTER TABLE — ADD COLUMNS (1, 2, 3) 
-- 1. Add column(s) (إضافة عمود واحد ثم إضافة عمودين معاً بين قوسين):
Alter table patients add date_birth date ;
Alter table patients add (x number , y number);

-- 2. Add column with default value (إضافة عمود بقيمة افتراضية):
alter table patients add gender varchar2(15) default 'not defined';

-- 3. Add column with constraint (إضافة عمود مع قيد):
alter table patients add z number not null;
alter table patients add xx number check(xx > 0);

🔧 ثالثاً: العمليات (٤ و ٥ و ٦) — تعديل خصائص عمود موجود بـ MODIFY

لو العمود موجود بالفعل في الجدول وعايز تغير الـ Datatype بتاعه، أو تغير الـ Size (الحجم)، أو تحوله لـ NOT NULL أو NULL، بنستخدم كلمة MODIFY:

ALTER TABLE — MODIFY COLUMNS (4, 5, 6) 
-- 4. Modify column(s) datatype or size (تغيير النوع من number لـ varchar2 ثم تكبير الحجم):
alter table patients modify z varchar2(50);
alter table patients modify z varchar2(100);

-- 5. Make column Not null (تحويل عمود موجود ليصبح إجباري Not Null):
alter table patients add w number;
alter table patients modify w not null;

-- 6. Remove not null / column with null (إلغاء الـ Not Null ليرجع يقبل Null عادي):
alter table patients modify w null;

جدول مقارنة مهم: إمتى نستخدم ADD وإمتى نستخدم MODIFY؟

وجه المقارنة أمر ALTER TABLE ... ADD أمر ALTER TABLE ... MODIFY
متى نستخدمه؟ لإضافة عمود جديد أو Constraint جديد مكنش موجود في الجدول لتعديل عمود موجود أصلاً في الجدول
التعامل مع NOT NULL لا نستخدم ADD CONSTRAINT مع NOT NULL نستخدم MODIFY col NOT NULL أو MODIFY col NULL

🗑️ رابعاً: العمليتان (٧ و ٨) — حذف الأعمدة DROP وإعادة التسمية RENAME

العملية رقم 7: حذف عمود واحد مقابل حذف عدة أعمدة (تركة امتحانات مشهورة جداً!)

خلي بالك أوي من الفرق في الـ Syntax بين السطرين دول في أوراكل:

  • لو هتحذف عمود واحد بس: لازم تكتب كلمة COLUMN بعد DROP، وبدون أقواس.
  • لو هتحذف أكتر من عمود مع بعض: ممنوع تكتب كلمة COLUMN، ولازم تحط أسماء الأعمدة كلها بين قوسين!
ALTER TABLE — DROP & RENAME (7, 8) 
-- 7. Drop column(s):
-- أ) حذف عمود واحد فقط (لازم نكتب كلمة column بدون أقواس):
alter table patients drop column date_birth;

-- ب) حذف عدة أعمدة معاً (ممنوع كلمة column ولازم أقواس):
alter table patients drop (x, y, z, gender, xx, w);

-- 8. Rename column & Rename table:
-- أ) تغيير اسم عمود من name إلى pname ثم إرجاعه لـ name:
alter table patients rename column name to pname;
alter table patients rename column pname to name;

-- ب) تغيير اسم الجدول نفسه من patients إلى ppatients ثم إرجاعه:
alter table patients rename to ppatients;
alter table ppatients rename to patients;

🔒 خامساً: العمليات (٩ و ١٠ و ١١) — إضافة وحذف وتعطيل وتفعيل الـ Constraints

بعد ما الجدول اتعمل، تقدر تضيف عليه Constraint جديد، أو تمسحه نهائياً بـ DROP CONSTRAINT، أو توقفه مؤقتاً بـ DISABLE وترجع تشغله بـ ENABLE:

ALTER TABLE — ADD, DROP, DISABLE & ENABLE CONSTRAINT (9, 10, 11) 
-- 9. Add constraint (إضافة قيد جديد لجدول موجود بصيغة Table-Level):
alter table patients add constraint age_chk_const check(age > 0);
alter table patients add constraint pk_add_const unique(address);

-- 10. Remove constraint (حذف القيد نهائياً باسمه):
alter table patients drop constraint age_chk_const;
alter table patients drop constraint pk_add_const;

-- 11. Enable and Disable Constraint (تعطيل القيد مؤقتاً ثم إعادة تفعيله):
alter table patients disable constraint age_chk_const;
alter table patients enable constraint age_chk_const;

مقارنة بين DROP CONSTRAINT و DISABLE CONSTRAINT:

وجه المقارنة DROP CONSTRAINT DISABLE CONSTRAINT
تأثيره على القيد بيمسح الـ Constraint نهائياً من الداتابيز بيوقف عمل الـ Constraint مؤقتاً بس بيفضل متسجل في الجدول
إزاي نرجعه يشتغل تاني؟ لازم تكتبه من أول وجديد بجملة ADD CONSTRAINT كاملة بتكتفي بأمر ENABLE CONSTRAINT constraint_name فقط

ALTER TABLE Patients ADD birth_date date;

-- 2. إضافة عمود بقيمة Default:

ALTER TABLE Patients ADD national_code number not null;

ALTER TABLE Patients MODIFY national_code varchar2(30);

Section 2 — Part 2 (Chapter 9: DML & TCL)

السكشن الثاني (الجزء الثاني): التعامل مع البيانات (INSERT, UPDATE, DELETE)

نبدأ الأول بتشريح كل أمر من أوامر الـ DML والـ TCL وصيغته العامة، وبعدها ندخل في الشرح التفصيلي لأكواد السكشن والمقارنات والتطبيق الشامل.

🔍 أولاً: تشريح وشرح كل أمر من أوامر DML & TCL بالتفصيل (الصيغة العامة + الوظيفة)

أوامر الـ DML هي المسؤولة عن إضافة وتعديل وحذف الصفوف داخل الجدول، وأوامر الـ TCL هي المسؤولة عن حفظ هذه التعديلات أو التراجع عنها:

١. أمر إضافة صف: INSERT INTO ... VALUES إدخال بيانات جديدة — DML

وظيفته: يضيف صفاً جديداً من البيانات داخل الجدول. إذا لم تكتب أسماء الأعمدة يجب إدخال قيم لكل الأعمدة بنفس ترتيب الجدول، وإذا كتبت أسماء الأعمدة تلتزم بالترتيب الذي كتبته.

SYNTAX: INSERT INTO 
-- 1. بدون تحديد أسماء الأعمدة (كل القيم بنفس ترتيب الجدول):
INSERT INTO table_name
VALUES (value1, value2, value3, ...);

-- 2. مع تحديد أسماء الأعمدة:
INSERT INTO table_name (col1, col2, ...)
VALUES (val1, val2, ...);
٢. أمر الإضافة الجماعية: INSERT ALL ... SELECT 1 FROM dual إضافة عدة صفوف أو عدة جداول

وظيفته: يتيح إدخال أكثر من صف في نفس الجدول أو في جداول مختلفة داخل جملة واحدة في أوراكل. شرطه الأساسي: يجب أن ينتهي في السطر الأخير بجملة SELECT 1 FROM dual;.

SYNTAX: INSERT ALL 
INSERT ALL
    INTO table1 [(col1, col2)] VALUES (val1, val2)
    INTO table2 [(col1, col2)] VALUES (val3, val4)
SELECT 1 FROM dual;
٣. أمر تعديل البيانات: UPDATE ... SET ... WHERE تحديث قيم موجودة — DML

وظيفته: يعدل قيمة عمود أو أكثر في الصفوف الموجودة بالجدول. كلمة SET تحدد القيم الجديدة، وجملة WHERE تحدد الصفوف المطلوب تعديلها (وإذا حذفت WHERE يتم تعديل كل صفوف الجدول).

SYNTAX: UPDATE 
UPDATE table_name
SET column1 = new_value1 [, column2 = new_value2]
[WHERE condition];
٤. أمر حذف الصفوف: DELETE FROM ... WHERE حذف صفوف مع إمكانية التراجع — DML

وظيفته: يحذف صفاً معيناً أو مجموعة صفوف بناءً على شرط WHERE، وإذا كُتب بدون WHERE يحذف جميع صفوف الجدول.

SYNTAX: DELETE 
-- حذف صفوف محددة بشرط:
DELETE FROM table_name WHERE condition;

-- حذف جميع الصفوف في الجدول:
DELETE FROM table_name;
٥. أمرا الحفظ النهائي والتراجع: COMMIT و ROLLBACK التحكم في الحفظ — TCL

وظيفة COMMIT: يحفظ جميع عمليات الـ DML السابقة بشكل دائم في قاعدة البيانات.
وظيفة ROLLBACK: يتراجع ويلغي جميع عمليات الـ DML التي تمت منذ آخر COMMIT.

SYNTAX: COMMIT & ROLLBACK 
COMMIT;
ROLLBACK;

📥 ثانياً: شرح أكواد السكشن لأمر الإضافة INSERT INTO (الأربع طرق بالتفصيل)

في كود السكشن عندك مشروح 4 طرق مختلفة لإدخال صفوف جديدة في الجدول:

1. إضافة صف واحد بدون كتابة أسماء الأعمدة:

لو مكتبتش أسماء الأعمدة بعد اسم الجدول، يبقى إجباري تدخل قيم لكل الأعمدة اللي في الجدول، وبنفس ترتيبها الأصلي وقت إنشاء الجدول (وخلي بالك: النصوص بتتحط بين 'Single Quotes' والأرقام بتتكتب مباشرة):

1. INSERT WITHOUT COLUMN LIST 
insert into doctors
values(123, 'DR.Mirna', 'Dematalogy', 10);

2. إضافة صف مع تحديد أسماء الأعمدة بترتيب من اختيارك:

هنا بتفتح قوسين بعد اسم الجدول وتكتب أسماء الأعمدة بأي ترتيب يعجبك، المهم في الـ VALUES تحت تلتزم بنفس الترتيب اللي أنت كتبته بين القوسين:

2. INSERT WITH CUSTOM COLUMN LIST 
insert into doctors (speciality, dname, dssn, exp_years)
values('Dematology', 'DR.Omar', 124, 5);

3. إدخال قيمة NULL في عمود (بالطريقة الضمنية والطريقة الصريحة):

في الكود عندك، عملنا الأول MODIFY لعمود exp_years عشان يقبل NULL، وبعدها دخلنا قيمة فاضية بطريقتين:

  • الطريقة الضمنية (Implicit NULL): تكتب أسماء الأعمدة التانية بس ومتكتبش اسم عمود exp_years أصلاً، فأوراكل هيحط فيه NULL لوحده.
  • الطريقة الصريحة (Explicit NULL): تكتب كلمة null بإيدك صراحةً جوه الـ VALUES.
3. INSERTING NULL (IMPLICIT VS EXPLICIT) 
-- أولاً نخلي العمود يقبل NULL:
Alter table doctors modify exp_years null;

-- أ) الطريقة الضمنية (تجاهل ذكر عمود exp_years في القائمة):
insert into doctors (speciality, dssn, dname)
values('Internal medicine', 125, 'DR.Nada');

-- ب) الطريقة الصريحة (كتابة كلمة null مباشرة في القيم):
insert into doctors
values(126, 'DR.Ali', 'Internal medicine', null);

4. إضافة عدة صفوف دفعة واحدة في جدول أو أكثر بـ INSERT ALL:

في أوراكل، لو عايز تضيف كذا صف في أمر واحد (سواء في نفس الجدول أو في جدولين مختلفين مع بعض)، بنستخدم INSERT ALL، ولازم نختمها في آخر سطر بجملة SELECT 1 FROM dual;:

4. INSERT ALL (MULTIPLE ROWS / MULTIPLE TABLES) 
-- أ) إضافة صفين في نفس الجدول (doctors) مرة واحدة:
insert all
    into doctors values(127, 'DR.Youmna', 'Dermatology', 3)
    into doctors values(128, 'DR.Marwan', 'General Pediatrics', null)
select 1 from dual;

-- ب) إضافة صف في جدول doctors وصف في جدول patients في نفس الأمر:
insert all
    into doctors(dname, dssn, speciality) values('DR.Eman', 129, 'Neurosurgery')
    into patients values(1, 'Mohamed', 55, 'Zagazig', 123)
select 1 from dual;

أمر UPDATE بيعدل بيانات موجودة فعلاً في الجدول. وخلي بالك من الفرق بين التعديل بدون WHERE والتعديل بـ WHERE:

UPDATE COMMAND (ALL ROWS VS SPECIFIC ROWS) 
-- 1. update column for all rows (بدون WHERE -> هيعدل كل الدكاترة اللي في الجدول!):

set exp_years = 2;

-- 2. update 2 columns for all rows (تعديل عمودين معاً لكل الصفوف، بنفصل بينهم بفاصلة):
update doctors
set exp_years = 5, speciality = 'Dematology';

LAB 1_ER DIAGRAM — PROBLEM STATEMENT 
The pharmacy database system is designed to manage the interactions among patients, doctors,
pharmacies, pharmaceutical companies, and drugs through prescriptions.
• Each Patient is uniquely identified by their Social Security Number (SSN), and additional information such
  as name, age, and address is stored.
• Each Doctor is uniquely identified by DSSN and has attributes such as name, specialty, and years of
  experience. A doctor can prescribe drugs to multiple patients, and a patient can receive multiple
  prescriptions from different doctors.
• A Prescription is a central entity in the system and is uniquely identified by a prescription ID (Pre_id).
  Each prescription records the date and quantity of a drug prescribed, and it connects a patient, a doctor,
  a pharmacy, and a drug.
• Each Drug is uniquely identified by its trade name, and its formula is also recorded.
• Drugs are manufactured by exactly one Pharmaceutical Company, which is identified by its company
  name (CName) and phone number.
• Each Pharmacy is uniquely identified by its name, and it stores details such as phone number and
  address. Pharmacies dispense prescriptions and sell drugs manufactured by pharmaceutical companies.

تفريغ معطيات السؤال (6 كيانات Entities):

  1. كيان Patient: الـ Primary Key هو SSN، والـ Attributes هي: Name, Age, Address.
  2. كيان Doctor: الـ Primary Key هو DSSN، والـ Attributes هي: Name, Specialty, EXP_Years.
  3. كيان Pharm_Company: الـ Primary Key هو CName، والـ Attribute هو: Phone.
  4. كيان Drug: الـ Primary Key هو Trade_Name، والـ Attribute هو: Formula.
  5. كيان Pharmacy: الـ Primary Key هو Pname، والـ Attributes هي: Phone, Address.
  6. كيان Prescription (الروشتة): الـ Primary Key هو Pre_id، والـ Attributes هي: Date, Quantity.
